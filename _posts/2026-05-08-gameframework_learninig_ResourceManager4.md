# ResourceManager 工作流总览

下面是整个资源管理器 `ResourceManager` 的工作流总览，不涉及具体代码，只关注流程和职责。

## 1. 初始化配置

游戏启动时，先配置资源系统：

```text
设置只读区路径
设置读写区路径
设置资源模式
设置当前资源变体
设置对象池管理器
设置文件系统管理器
设置下载管理器
设置资源辅助器
添加资源加载代理
```

只读区一般是包体资源目录。

读写区一般是热更新下载目录。

资源模式决定后续流程是单机模式还是可更新模式。

## 2. 资源模式分流

资源管理器主要有三种模式：

```text
Package
单机模式，只使用包体资源。

Updatable
可更新模式，启动时检查并下载资源。

UpdatableWhilePlaying
边玩边下模式，资源需要时再下载。
```

不同模式会创建不同的内部模块。

单机模式主要使用：

```text
ResourceIniter
```

可更新模式主要使用：

```text
VersionListProcessor
ResourceVerifier
ResourceChecker
ResourceUpdater
```

## 3. 单机模式流程

单机模式比较简单：

```text
读取只读区版本资源列表
解析 Asset、Resource、ResourceGroup 信息
建立资源索引
资源全部标记为 Ready
进入加载阶段
```

它不会下载资源，也不会检查远端版本。

核心结果是建立两张运行时索引：

```text
Asset -> Resource
Resource -> 位置、加载方式、状态
```

## 4. 可更新模式流程

可更新模式会更完整。

首先，上层从服务器获取最新版本信息。

然后资源管理器检查本地是否已有最新版本资源列表。

如果本地版本列表过期：

```text
下载最新版本资源列表
校验长度和 hash
解压
保存到读写区
```

接着可以选择校验读写区已有资源：

```text
读取读写区本地资源表
逐个检查资源文件是否存在、长度是否正确、hash 是否正确
坏资源删除
重新生成读写区资源表
```

然后进入资源检查阶段：

```text
读取最新版本表
读取只读区资源表
读取读写区资源表
对比每个资源状态
```

资源会被判断为：

```text
只读区可用
读写区可用
需要更新
不适合当前变体
已废弃
```

需要更新的资源会被登记到更新器中。

## 5. 资源补齐

资源缺失时，有两种补齐方式。

一种是应用资源包：

```text
读取离线资源包
找出其中能匹配当前缺失资源的内容
写入读写区
校验
标记资源 Ready
```

另一种是联网下载：

```text
根据资源名和 hash 拼接远程 URL
下载到读写区
校验压缩长度和 hash
解压
校验最终资源
写入磁盘或文件系统
标记资源 Ready
```

资源补齐成功后，资源管理器会更新读写区资源表：

```text
ReadWritePath/GameFrameworkList.dat
```

这样下次启动时就知道这些资源已经下载过，不用重复下载。

## 6. 建立资源索引

无论单机还是可更新模式，最终都要建立运行时索引。

主要有两类：

```text
AssetInfo
记录某个 Asset 属于哪个 Resource，以及依赖哪些 Asset。

ResourceInfo
记录某个 Resource 在哪里、是否 Ready、加载方式、长度、hash、是否在文件系统中。
```

加载资源时，资源管理器靠这两类信息找到资源。

## 7. 加载资源

当业务层调用加载：

```text
LoadAsset
LoadScene
LoadBinary
```

资源管理器会先查：

```text
Asset 是否存在
Resource 是否存在
Resource 是否 Ready
依赖资源有哪些
```

然后创建加载任务，放入任务池。

任务池每帧分配空闲加载代理来处理任务。

加载代理会：

```text
检查对象池是否已有 Asset
检查依赖是否加载完
检查资源包是否已经在 ResourcePool
必要时读取资源包
从资源包加载具体 Asset
```

真正的底层读取和加载由外部 Helper 实现。

## 8. 对象池缓存

资源管理器有两个重要对象池：

```text
ResourcePool
缓存资源包对象，比如 AssetBundle。

AssetPool
缓存具体资源对象，比如 Prefab、Texture、AudioClip。
```

如果资源已经在池子中，下次加载可以直接复用，不需要重新读取或重新加载。

## 9. 加载完成

加载完成后：

```text
资源包包装成 ResourceObject，放入 ResourcePool
具体 Asset 包装成 AssetObject，放入 AssetPool
建立 Asset 和 Resource 的关系
记录依赖关系
触发加载成功回调
任务结束
加载代理回到空闲状态
```

业务层最终拿到加载出来的资源对象。

## 10. 卸载资源

卸载时，资源管理器不会立刻粗暴销毁所有东西，而是交给对象池管理。

```text
UnloadAsset
-> AssetPool.Unspawn
-> 资源变为未使用状态
```

对象池会根据引用关系、依赖关系、过期时间、容量等规则决定什么时候真正释放。

释放 Asset 时，会减少依赖 Asset 的引用计数。

释放 Resource 时，也会检查是否还有 Asset 依赖它。

这样可以避免资源还被使用时误释放。

## 整体总结

```text
ResourceManager 负责从版本表建立资源索引，
根据资源模式判断资源是否需要更新，
把缺失资源补齐到读写区，
然后通过任务池、加载代理、对象池完成资源加载和复用。
```

最完整的主线是：

```text
配置资源系统
-> 选择资源模式
-> 读取/更新版本列表
-> 建立资源索引
-> 检查资源状态
-> 下载或应用缺失资源
-> 标记资源 Ready
-> 加载资源
-> 缓存到对象池
-> 使用和卸载资源
```
